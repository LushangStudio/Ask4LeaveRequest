# 班级管理

服务器在 /etc/ask4leave/ask4leave.env 中设置 ADMIN_USER_IDS，英文逗号分隔 UIS 学工号。修改后重启 ask4leave；管理员无需加入学生或辅导员名单。进入 /leave/class-management/ 管理班级和学生。

## 数据结构

- directory_classes：class_id（UUID）、name（名称）、grade（年级）、department（院系）。
- class_counselors：class_id（班级 UUID）、user_id（辅导员学工号），联合主键。
- directory_students：user_id（学号）、major（专业）、class_id（班级 UUID）。

不再单独维护辅导员名单，班级关联中出现的学工号自动获得辅导员身份。学生仍只有一个班级；可兼任辅导员，包括自己所在班级；一个班级至少配置一位辅导员。UUID 仅用于内部关联，界面显示“名称 · 年级 · 院系”，不展示 UUID。

班级表单填写名称、年级、院系和辅导员学工号（英文逗号分隔）。学生表单填写学号、专业并下拉选择班级。保存后立即生效，删除最后一个辅导员关联会停用其辅导员身份；管理员权限仍由 ADMIN_USER_IDS 决定。历史申请、审批、签名和 PDF 保留，关系修改只影响新申请。

class_directory 保留 version=2 的整份配置及乐观锁摘要，用于管理页面并发检查；三张关系表与配置、people 权限投影在同一事务中同步，失败整体回滚。people.profile 是供工作台使用的派生资料，年级和院系来源于班级，不作为可编辑的学生字段。

## 导入

先保存当前编辑，再下拉选择导入班级。CSV 只接受两列，可带表头：

```csv
学号,专业
0000123,工商管理
0000124,管理科学
```

保留学号前导零，英文逗号分隔，包含逗号的专业使用双引号。旧五列/六列 CSV 会报错。先预览，再确认；同学号更新专业与所属班级，未出现的学生保留。未知班级、重复学号、空专业或非法学号会拒绝整批导入，名单版本变化时必须刷新重新预览。每批最多 5000 人。

## 姓名

师生与管理员姓名来自 UIS 登录的 user_name，仅缓存在当前单进程会话内存中，不写入人员名册。提交请假和审批时写入各自历史快照及 PDF。重启后需要重新登录，当前单 worker 模式不能直接扩展为多 worker。演示/测试身份使用学工号替代姓名。

## 升级与回退

先备份数据库，用迁移账号执行 docs/migrations/009-normalized-directory.mysql.sql，再部署新版。运行账号保留原有 DML 权限，不授予 DDL。首次启动将旧 version=1 名册转换为 version=2，生成稳定 UUID，迁移学生关联和班级辅导员关联，并同步三张表，不修改历史请假快照。

旧班级的年级、院系从已有学生提取；同一班级出现多个年级或院系时拒绝迁移，须先整理旧资料，不能静默挑选。没有学生的旧班级用“待完善”占位，管理员应补齐。旧未关联任何班级的辅导员不再保留独立身份。迁移会清空 people.name（含停用人员），历史备份不做改写。

version=2 写入后，旧程序不能直接读取新配置。回退必须停服，先恢复迁移前备份，再切回旧代码。不要只切换 release 链接。发布前应先以新版 DirectoryConfig 校验数据库中的旧名单，确认无歧义；迁移后核验表数量、关系数、名单版本和健康接口。
